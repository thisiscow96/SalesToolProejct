## 2. 바꾼 구성 (전부 무료)

### 같이 고친 보안 문제
- **운영에서 인증번호가 응답에 노출되던 문제:** 메일 발송이 실패하면 API가 `dev_code`로 인증번호를 돌려줘, 누구나 이메일 인증을 건너뛸 수 있었다. 이제 개발 환경에서만 노출되고(`EXPOSE_DEV_CODE`), 운영에서는 HTTP 503과 안내 문구를 돌려준다.
- **중매인 번호만 알면 남의 데이터를 보던 문제 (T-101, 2026-11-20):** 예전 API는 `X-Agent-No` 헤더(중매인 번호)만으로 사용자를 정했다. 이제 로그인 성공 시 서버가 `AUTH_SECRET`으로 서명한 토큰(JWT·HS256, 기본 12시간)을 주고, 보호 API는 `Authorization: Bearer <토큰>`만 믿는다. 헤더만 바꾼 호출·위조·변조·만료 토큰은 모두 401이며, 프론트는 401을 받으면 로그인 화면으로 보낸다. **운영에서 `AUTH_SECRET`이 없으면 서버가 시작하지 않는다.**

## 3. 문자(SMS) 인증 — "무료·무제한"은 없다
- 한국 문자는 통신사 망을 쓰므로 **건당 비용이 반드시 발생**한다. Firebase 전화 인증도 2024-09부터 결제 계정이 필요하고 문자마다 과금된다.
- 비용 없이 본인 확인을 하려면 아래 중 하나를 고른다.

| 방법 | 비용 | 한도 | 장단점 |
|---|---|---|---|
| **이메일 인증 (지금 방식)** | 무료 | 하루 약 900통(위 3개 합산) | 추가 개발 없음. 가입자 규모(중매인)에 충분 |
| **카카오·네이버·구글 로그인** | 무료 | 사실상 제한 없음 | 휴대폰 번호까지 받으려면 카카오는 비즈 앱 전환·동의항목 심사 필요. 로그인 화면·회원 연결 개발 필요 |
| Firebase Phone Number Verification | 확인 필요 | — | 2026-05 출시, 문자 대신 SIM 정보로 확인. 모바일 앱 중심 |
| 유료 문자(SOLAPI·알리고 등) | 건당 과금 | 충전한 만큼 | 진짜 "문자 인증"이 꼭 필요할 때만 |

→ **권장:** 지금처럼 이메일 인증을 유지하고(무료 한도 3배로 확장됨), 휴대폰 확인이 꼭 필요하면 카카오 로그인을 다음 단계로 추가한다.

## 4. 전환 순서 (계정 만들기는 직접)
1. **Neon** 가입 → 프로젝트 생성(리전: 가까운 곳, 예 Singapore) → 연결 문자열 복사(`?sslmode=require` 포함)
2. GitHub → Settings → Secrets → Actions
   - `DATABASE_URL` = Neon 연결 문자열
   - (옛 Render DB가 아직 살아 있으면) `SOURCE_DATABASE_URL` = Render External URL
3. 데이터 옮기기
   - 옛 DB가 살아 있으면: Actions → **Copy database to new Postgres** → `COPY` 입력 → 실행
   - 이미 만료됐으면: Actions → **Migrate database** 실행 후 `npm run seed-admin`(로컬에서 `DATABASE_URL`을 Neon으로)
4. **Render** 백엔드 Environment에서 `DATABASE_URL`을 Neon으로 바꾸고, `NODE_ENV=production`, **`AUTH_SECRET`(32자 이상 임의 문자열 — `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`로 만들어 붙여 넣기, 저장소·문서에 적지 않음)**, 선택 `AUTH_TOKEN_TTL_HOURS`(기본 12), 메일 키(`RESEND_*`, `BREVO_*`) 설정 → 재배포 → `/api/capabilities`의 `mailProviders`로 확인
5. GitHub → Settings → Variables → `KEEPALIVE_URL` = `https://<render 주소>/` (`/health`는 DB 조회라 쓰지 않음) (잠들지 않게)
6. **Cloudflare Pages** → Create → GitHub 저장소 연결 → Root `web`, Build `npm run build`, Output `dist` → Environment variables `API_ORIGIN` = Render 주소 → 배포 → 도메인(garaksalestool.com) 연결
7. 확인 후 Vercel 프로젝트·Render DB 삭제

## 6. 휴대폰 확인 제거 — 이메일 인증만 (2026-11-20 사용자 결정)
- 가입 화면에서 휴대폰번호 입력·중복확인을 없앴다. 필수: 상호명 · 이메일(인증) · 중매인 번호 · 비밀번호.
- `POST /api/auth/check-phone` 제거. 가입 API는 `phone`을 받지 않아도 되고, 보내면 형식만 확인해 저장한다.
- DB `user.phone`은 `NOT NULL` 해제(`migrations/008_user_phone_optional.sql`). 기존 회원 번호는 그대로, 값이 있으면 중복 불가(UNIQUE 유지).
- 이메일이 유일한 본인 확인이 되어 보안을 보강: 인증번호 **오입력 5회면 그 번호 무효 → 재발송 필요**(HTTP 429), 인증번호는 `crypto.randomInt`로 생성. 서버는 기존대로 인증 15분 이내 이메일만 가입을 허용.
- 확인: 새 DB에 008 적용 → 인증 전 가입 거부 → 오입력 2회(남은 시도 표시) → 인증 → 휴대폰 없이 가입·로그인 성공(phone NULL) → 다른 이메일 5회 오입력 잠금(429) → 스모크 성공.

## 7. 마이그레이션 접속 주소·잠금 (2026-11-20, T-219 · DB 검토 R-03·R-04)
- **새 환경변수(선택) `MIGRATE_DATABASE_URL`**: 있으면 `scripts/migrate.js`가 `DATABASE_URL` 대신 이 주소로 접속한다. Neon이라면 호스트 이름에 `-pooler`가 **없는 직접 연결 주소**를 넣는다(Neon 콘솔 Connect → Connection pooling 끄기). 서버(`index.js`)는 계속 `DATABASE_URL`(풀러 가능)을 쓴다.
  - Render 백엔드 Environment, GitHub Actions Secrets(“Migrate database”를 쓸 때) 두 곳에 넣는다. 값은 저장소·문서·로그에 적지 않는다. migrate 로그에는 어느 변수를 썼는지와 풀러 주소인지만 나온다.
  - 없어도 동작한다. migrate.js 잠금은 파일마다 트랜잭션 잠금(`pg_advisory_xact_lock`)이라 풀러 주소에서도 잠금이 남지 않는다(예전 세션 잠금은 Neon 풀러에서 남아 다음 배포가 멈췄음 — 2026-11-20 운영 재현).
- 대기 한도: 파일마다 `lock_timeout`·`statement_timeout`을 건다. 열린 트랜잭션 때문에 테이블 잠금을 못 얻으면 그 파일만 롤백되고 migrate가 exit 1로 끝나 서버가 뜨지 않는다. 고칠 것 없이 다시 배포하거나 Actions “Migrate database”를 다시 돌린다.
- 013(`013_return_amount_overpaid.sql`)이 010 따라잡기 백필(`scripts/backfill-010-returns.sql`)을 포함한다 → 운영에서 이 스크립트를 따로 실행할 필요가 없다. 적용 뒤 `refund.credit_amount`는 NOT NULL·DEFAULT 0.
